## 0. ハンズオンの全体像

### 自動運転の基本：認知・判断・操作

自動運転システムは以下の3つのステップで動作します：

```
┌──────────┐    ┌──────────┐    ┌──────────┐
│  認知    │───→│  判断    │───→│  操作    │
│ (Sense)  │    │ (Plan)  │    │  (Act)   │
└──────────┘    └──────────┘    └──────────┘
   センサー        プランナー        モーター
```

### 今回の学習内容

1. **センサー制御**: 超音波センサー/カメラで周囲を認知
2. **手動運転**: ジョイスティックで基本操作を理解
3. **データ収集**: 走行データを記録
4. **機械学習**: End-to-Endで操作を学習
5. **自動走行**: 学習したモデルで自律走行

### 使用するハードウェア

- Raspberry Pi 4/5 または Jetson Orin Nano
- モーター（ESC制御）+ ステアリングサーボ
- 超音波センサー（HC-SR04）またはLiDAR
- カメラモジュール
- ゲームコントローラー（Logicool F710など）

## 1. ミニカーの動かし方（throttleとsteering）

### 1.1 モーターの基本理解

自動車の制御は**2つの値**で行われます：

- **Throttle（スロットル）**: 前後の速度 `-1.0`（後退）～ `0.0`（停止）～ `1.0`（前進）
- **Steering（ステアリング）**: 左右の向き `-1.0`（左）～ `0.0`（直進）～ `1.0`（右）

### 1.2 モーター調整

まず、モーターの動作範囲を確認します：

```bash
python motor.py
```

#### 調整手順

1. **ステアリングの調整**
   - 真ん中の値を探す（車輪が真っ直ぐになる値）
   - 左最大の値を探す
   - 右最大の値を探す

2. **スロットルの調整**
   - ニュートラル（モータードライバーが「ピッピッピ」と音を出す値）
   - 前進の最大値
   - 後進の最大値

> **注意**: 極端に大きな/小さな値を入れるとモーターを破損する恐れがあります！

3. **config.pyへ保存**

調整した値を `config.py` に記録します：

```python
# ステアリングのPWM値
STEERING_CENTER_PWM = 420
STEERING_WIDTH_PWM = 80
STEERING_RIGHT_PWM = STEERING_CENTER_PWM - STEERING_WIDTH_PWM
STEERING_LEFT_PWM = STEERING_CENTER_PWM + STEERING_WIDTH_PWM

# スロットルのPWM値
THROTTLE_STOPPED_PWM = 390
THROTTLE_FORWARD_PWM = 450
THROTTLE_REVERSE_PWM = 330
```

### 1.3 ジョイスティックで操作

ゲームコントローラーで実際に動かしてみましょう：

```bash
python run.py
```

#### コントローラー操作

```
        [LB]              [RB]
         ┌─────────────────┐
         │                 │
    [←→] │    [BACK] [S]   │  [Y]
    [↑↓] │                 │[X] [B]
         │   [LOGICOOL]    │  [A]
         │                 │
         │ [LSTICKB]       │     [RSTICKB]
         └─────────────────┘
```

- **左スティック（左右）**: ステアリング操作
- **右スティック（上下）**: スロットル操作
- **Yボタン**: データ記録の開始/停止
- **Sボタン**: 手動/自動モード切り替え

#### 練習課題

- [ ] 前進・後退を試す
- [ ] 左右に曲がる
- [ ] コースを1周する

### 1.4 ハンズオン用コース

今回のハンズオンで使用するコースは、様々な走行技術を学べるように設計されています。

![ハンズオン用コース](assets/images/course_hanson_0.png)

#### コースの特徴

このコースには4つの異なるタイプの走行区間が含まれています：

1. **ストレート区間**（左側の長い直線）
   - 速度制御とまっすぐ走行する技術を学ぶ
   - 一定のスロットル値を保つ練習に最適

2. **直角コーナー**（上部の90度カーブ）
   - シャープなハンドル操作が必要
   - 減速しながらのステアリング制御を学ぶ

3. **ジグザグコーナー**（右側のS字カーブ）
   - 連続した左右の切り返し操作
   - 細かいステアリング調整と速度制御のバランスが重要

4. **滑らかなコーナー**（下部のU字カーブ）
   - 緩やかで安定したハンドル操作
   - 一定の曲率で走行する技術を学ぶ

#### コース仕様

- **全長**: 約3m × 6m
- **コース幅**: 約1.5m（内外壁間）
- **壁の高さ**: 20cm～30cm
  - 超音波センサーやLiDARでの測距が可能な高さに設計
  - カメラでも壁を明確に認識できる

#### 走行のコツ

- **初めての走行**: まずは低速（スロットル0.3程度）で全体を把握する
- **ストレート**: スロットルを一定に保ち、ステアリングを真ん中に
- **直角コーナー**: 進入前に減速し、ゆっくりとハンドルを切る
- **ジグザグ**: 慌てず、一つずつのカーブを丁寧に曲がる
- **滑らかなコーナー**: 一定のハンドル角度を保ちながら通過する

## 2. センサーを動かして測距や画像を取得する

### 2.1 測距センサーの選択

このシステムでは2種類の測距センサーが利用できます：

| センサー | 超音波センサー | LiDAR |
|---------|--------------|-------|
| **検知範囲** | 狭い（約30度） | 広い（270-360度） |
| **検知距離** | 2cm～400cm | 10cm～2000cm以上 |
| **分解能** | ±3mm | ±数mm～数cm |
| **計測点数** | 3-5点 | 数百～千点以上 |
| **計測周期** | 約200-500ms（個数分） | 約25-125ms（機種による） |
| **価格** | 数百円 | １万円以上 |
| **用途** | 基本的な障害物検知 | 高精度な環境認識 |

### 2.2 超音波センサーの測定

超音波センサーで距離を測定してみましょう：

```bash
python ultrasonic.py
```

#### 超音波センサーの特性

- **検知角度**: 約15度（片側）
- **検知距離**: 2cm～400cm
- **測定精度**: ±3mm

```
        センサー
           |
          / \
         /   \
        /     \
   15° /       \ 15°
      /         \
```

#### 実験してみよう

1. **距離測定テスト**
   - 定規で実際の距離を測り、センサー値と比較する
   - 10cm、50cm、100cm、200cmで精度を確認

2. **検知範囲テスト**
   - 手をかざして検知角度（約±15度）を確認
   - センサーの向きを変えながら測定

3. **パラメータ変更実験**
   - `config.py`で`ULTRASONIC_SENSOR_LIST`の数を変える
   - `SAMPLING_TIMES`を変えて測定速度を調整

#### config.py設定例（超音波センサー）

```python
# アクティブセンサー
ACTIVE_SENSORS = ["ultrasonic", "camera_0", "camera_1"]

# 超音波センサーのピン設定
ULTRASONIC_SENSOR_LIST = [
    {"name": "RrLH", "trig": 17, "echo": 27},  # 左後方
    {"name": "FrLH", "trig": 22, "echo": 23},  # 左前方
    {"name": "FrFR", "trig": 24, "echo": 25},  # 前方
    {"name": "FrRH", "trig": 5, "echo": 6},    # 右前方
    {"name": "RrRH", "trig": 13, "echo": 19},  # 右後方
]
```

### 2.3 LiDARの測定（オプション）

LiDARはレーザースキャンで高精度な距離測定を行います：

```bash
python lidar.py
```

#### LiDARの特性

**対応機種:**
- **YDLIDAR TMINI**: 360度スキャン、シリアル接続、約400点
- **北陽 UST-20**: 270度スキャン、イーサネット接続、約1081点

**特徴:**
- **検知範囲**: 270度～360度（機種による）
- **検知距離**: 10cm～20m以上
- **測定精度**: 機種により数mm～数cm
- **スキャン点数**: 数百～千点以上

#### LiDARのゾーン分割

LiDARは高密度の点群データを取得しますが、超音波センサーと同じように**5つのゾーン**に分割して使用できます：

```
        前方
         ↑
    左前  FrFR  右前
FrLH  ←  [車]  → FrRH
    左後        右後
    RrLH       RrRH
```

| ゾーン名 | 説明 |
|---------|------|
| RrLH | 左後方 |
| FrLH | 左前方 |
| FrFR | 前方 |
| FrRH | 右前方 |
| RrRH | 右後方 |

#### 実験してみよう

1. **広範囲スキャン確認**
   - LiDARは360度または270度をスキャンするため、超音波より広範囲を認識
   - 車両の周囲を歩いて、どの位置で検出されるか確認

2. **点群密度の確認**
   - 1回のスキャンで数百～千点のデータを取得
   - 超音波センサー（3-5点）との違いを体感

3. **精密な距離測定**
   - 定規で実際の距離を測り、LiDAR値と比較
   - 超音波センサーと精度を比較

#### config.py設定例（LiDAR）

```python
# アクティブセンサー（LiDARを使用）
ACTIVE_SENSORS = ["lidar", "camera_0", "camera_1"]

# LiDARの有効化
HAVE_LIDAR = True
LIDAR_TYPE = "TMINI"  # または "UST20"

# TMINI設定例
TMINI_SERIAL_PORT = "/dev/ttyAMA0"
TMINI_SERIAL_BAUDRATE = 230400

# または UST-20設定例
# LIDAR_TYPE = "UST20"
# UST20_IP_ADDRESS = "192.168.0.10"
# UST20_PORT = 10940

# LiDAR検出閾値
LIDAR_DETECT_POINTS_THRESHOLD = 20  # 障害物と判定する最小点数
LIDAR_DETECT_DISTANCE_THRESHOLD = 300  # 障害物と判定する距離（mm）

# ゾーン別の距離閾値（必要に応じて調整）
LIDAR_DETECT_DISTANCE_THRESHOLD_ZONE = [
    300,  # RrLH: 左後方
    300,  # FrLH: 左前方
    200,  # FrFR: 前方（より近くで検出）
    300,  # FrRH: 右前方
    300,  # RrRH: 右後方
]
```

#### 超音波センサーとLiDARの切り替え

システムは自動的にどちらのセンサーでも同じインターフェースで扱えます：

```python
# 超音波センサーを使用する場合
ACTIVE_SENSORS = ["ultrasonic", "camera_0", "camera_1"]

# LiDARを使用する場合（切り替えるだけでOK）
ACTIVE_SENSORS = ["lidar", "camera_0", "camera_1"]

# 両方使用する場合（上級者向け）
ACTIVE_SENSORS = ["ultrasonic", "lidar", "camera_0", "camera_1"]
```

#### どちらを選ぶべき？

| 状況 | おすすめ |
|-----|---------|
| **初心者・コスト重視** | 超音波センサー |
| **高精度・広範囲が必要** | LiDAR |
| **屋内の狭い場所** | 超音波センサー |
| **複雑な環境** | LiDAR |
| **学習用データ収集** | どちらでも可（LiDARがより豊富） |

## 3. ミニカーを走らせて走行データをとる

### 3.1 データ記録の準備

`config.py`で設定を確認：

```python
# 走行プラン（手動モードで記録）
PLAN = "manual"

# データ保存形式
SAVE_FORMAT = "donkeycar"  # 画像ベースの学習用

# 記録するセンサー（超音波センサーの場合）
ACTIVE_SENSORS = ["ultrasonic", "camera_0", "camera_1"]

# または LiDARを使用する場合
# ACTIVE_SENSORS = ["lidar", "camera_0", "camera_1"]
```

> LiDARを使用する場合、超音波センサーよりも高密度のセンサーデータが記録されます。これにより、より詳細な環境情報を学習に活用できます。

### 3.2 走行データの記録

```bash
python run.py
```

#### 記録手順

1. **Yボタンを押す** → 記録開始（LEDやターミナルに表示）
2. **コースを走行** → ジョイスティックで操作しながら走る
   - できるだけ滑らかに操作する
   - コースの様々な場所を走る
   - 最低3周は走行する
3. **Yボタンをもう一度押す** → 記録停止

#### 記録のコツ

- **滑らかな操作**: 急なハンドル操作は避ける
- **多様なデータ**: 直線、カーブ、様々な状況を記録
- **十分な量**: 最低でも1000フレーム以上（約3-5周）

### 3.3 データの確認

記録されたデータは `data/` フォルダに保存されます：

```
└── 20251205_143022/

    ├── record_00002.json
    ├── images/
    │   ├── 00001_cam0.jpg
    │   ├── 00001_cam1.jpg
    │   └── ...
    └── manifest.json
```

## 4. 走行データを分析する

### 4.1 データ可視化ツール（graph.py）

Webベースの可視化ツールでデータを確認します：

```bash
cd tools
python graph.py
```

ブラウザで `http://localhost:8050` にアクセス

#### 機能

**graph.py**は走行データを視覚的に分析するためのWebアプリケーションです：

1. **データ読み込み**
   - CSV形式のデータに対応
   - NDJSON形式のデータに対応
   - `data/`フォルダから自動検出

2. **グラフ表示**
   - ステアリング値の推移
   - スロットル値の推移
   - 超音波センサー/LiDARの距離データ
   - インタラクティブな拡大・縮小

3. **画像表示**
   - タイムスライダーで任意の時点の画像を表示
   - カメラ0、カメラ1の切り替え
   - 操作値とセンサー値の同時確認

4. **統計情報**
   - 📊 データ数（総レコード数）
   - ⏱️ 記録時間
   - 🎯 走行モード
   - 📷 画像数

#### 使い方

1. **ツールを起動**
   ```bash
   cd tools
   python graph.py
   ```

2. **ブラウザでアクセス**
   - URLを開く: `http://localhost:8050`

3. **データファイルを選択**
   - ドロップダウンから走行データを選択
   - 自動的にグラフが表示される

4. **データを分析**
   - グラフをマウスでドラッグして拡大
   - タイムスライダーで画像を確認
   - 問題のある箇所を特定

### 4.2 データクレンジングツール（cleanup_empty_data.py）

空のデータフォルダを削除してデータを整理します：


#### 機能

**cleanup_empty_data.py**は不要なデータフォルダを自動削除します：

1. **削除対象**

   - manifest.jsonのみのフォルダ

2. **保持するもの**
   - 実際の走行データがあるフォルダ
   - 画像ファイルが含まれるフォルダ
   - catalogファイルがあるフォルダ

#### 使い方

```bash
# dataフォルダ内の空フォルダを削除

```

**実行例:**

**いつ使う？**

- ディスク容量を節約したい時

### 4.3 確認項目

#### 操作値の分布

- **ステアリング**: 左右均等に操作できているか
- **スロットル**: 一定速度を保てているか

#### センサー値の変化

- 障害物との距離が適切に記録されているか
- カメラ画像が鮮明か

#### データの質

- **ノイズ**: 急激な操作変化がないか
- **バイアス**: 左右どちらかに偏っていないか
- **データ量**: 十分な量があるか（1000フレーム以上推奨）

### 4.4 問題があった場合の対処法

#### データ量が不足

**症状:**
- グラフに表示されるデータが少ない
- 記録時間が短い（1分未満）

**対処:**
```bash
# 追加で走行データを収集
python run.py
# Yボタンで記録開始 → 3周以上走行 → Yボタンで記録停止
```

#### 操作が荒い（ノイズが多い）

**症状:**
- ステアリンググラフがギザギザ
- 急激な操作変化が頻繁にある

**対処:**
- より滑らかに運転して再記録
- スロットルを一定に保つ
- ステアリングは徐々に切る

#### データに偏りがある

**症状:**
- ステアリングが左右どちらかに偏っている
- 特定のコーナーのデータが少ない

**対処:**
- バランスよく走行して補完
- 苦手な区間を重点的に走行
- 逆回りでも走行してデータを収集

#### 画像が不鮮明

**症状:**
- カメラ画像がブレている
- 画像が暗すぎる/明るすぎる

## 5. 機械学習モデルの理解

### 5.1 利用可能なモデル一覧

このシステムでは、用途に応じて複数のモデルから選択できます：

| モデル名 | 入力データ | 特徴 | 学習時間 | 推論速度 | おすすめ度 |
|---------|----------|------|---------|---------|-----------|
| **donkeycar** | 画像 | 軽量CNN、バランス型 | 中 | 速い | ★★★★★ |
| **nn** | センサー値 | 全結合NN、シンプル | 短 | 非常に速い | ★★★☆☆ |
| **resnet18** | 画像 | 高精度、事前学習済み | 長 | 中 | ★★★★☆ |
| **mobilevit_xxs** | 画像 | Vision Transformer | 中 | 中 | ★★★☆☆ |
| **edgenext_xxsmall** | 画像 | エッジ最適化 | 中 | 速い | ★★★★☆ |

### 5.2 各モデルの詳細

#### 1. donkeycar（軽量CNN）

**概要:**
- DonkeyCarプロジェクトの軽量畳み込みニューラルネットワーク
- ハンズオンで最もおすすめのモデル

**構造:**
```
入力画像(224x224x3)
    ↓
Conv2D → Conv2D → Conv2D  (特徴抽出)
    ↓
全結合層 → 出力(steering, throttle)
```

**特徴:**
- ✅ 軽量で高速（約600 FPS）
- ✅ 学習時間が短い（30エポックで約10-20分）
- ✅ Raspberry Piでも動作可能
- ✅ バランスが良く、初心者に最適

**使用例:**
```python
PLAN = "donkeycar"
MODEL_INPUT_IMAGE = "cam1/image_array"
EPOCHS = 30
```

#### 2. nn（ニューラルネットワーク）

**概要:**
- 超音波センサー/LiDARの距離データから操作を学習
- 画像を使わないシンプルなモデル

**構造:**
```
センサー入力(5値)
    ↓
全結合層(64) → 全結合層(64) → 全結合層(64)
    ↓
出力(steering, throttle)
```

**特徴:**
- ✅ 非常に軽量（数KB）
- ✅ 学習が高速（10エポックで数分）
- ✅ カメラ不要
- ⚠️ 画像モデルより精度は劣る

**使用例:**
```python
PLAN = "nn"
HIDDEN_DIM = 64  # 隠れ層のノード数
NUM_HIDDEN_LAYERS = 3  # 隠れ層の数
EPOCHS = 30
```

**どんな時に使う？**
- ルールベースとNNモデルベースの制御を学びたい時

#### 3. resnet18（ResNet18）

**概要:**
- 深層残差ネットワーク（Residual Network）
- ImageNetで事前学習済みのモデルを転移学習

**構造:**
```
入力画像(224x224x3)
    ↓
18層の残差ブロック（特徴抽出）
    ↓
全結合層 → 出力(steering, throttle)
```

**特徴:**
- ✅ 高精度（複雑なコースに強い）
- ✅ 事前学習済み（少ないデータでも学習可能）
- ✅ 安定した性能
- ⚠️ 学習時間が長い（30エポックで30-60分）
- ⚠️ モデルサイズが大きい（約45MB）

**使用例:**
```python
PLAN = "resnet18"
MODEL_INPUT_IMAGE = "cam1/image_array"
EPOCHS = 30
```

**どんな時に使う？**
- 高精度が必要な時
- 複雑なコースに挑戦する時
- Jetsonなど高性能なハードウェアを使う時

#### 4. mobilevit_xxs（MobileViT）

**概要:**
- Vision Transformerのモバイル最適化版
- 注意機構（Attention）を使った最新アーキテクチャ

**構造:**
```
入力画像(224x224x3)
    ↓
MobileNetV2ブロック + Transformerブロック
    ↓
全結合層 → 出力(steering, throttle)
```

**特徴:**
- ✅ Transformer系で最も軽量
- ✅ 広範囲の特徴を捉えられる
- ✅ TensorRT最適化で3.9倍高速化
- ⚠️ PyTorchのままだと遅い（約34 FPS）

**使用例:**
```python
PLAN = "mobilevit_xxs"
MODEL_INPUT_IMAGE = "cam1/image_array"
INFERENCE_ENGINE = "tensorrt"  # TensorRT推奨
EPOCHS = 30
```

**どんな時に使う？**
- 最新のTransformer技術を試したい時
- Jetson + TensorRTで高速化できる時
- 広い視野が必要なコースの時

#### 5. edgenext_xxsmall（EdgeNeXt）

**概要:**
- エッジデバイス向けに最適化された最新モデル
- ConvNeXtのモバイル版

**構造:**
```
入力画像(224x224x3)
    ↓
軽量ConvNeXtブロック（エッジ最適化）
    ↓
全結合層 → 出力(steering, throttle)
```

**特徴:**
- ✅ エッジデバイスで最高の性能
- ✅ TensorRT最適化で5.15倍高速化（最高）
- ✅ 軽量ながら高精度
- ✅ メモリ効率が良い

**使用例:**
```python
PLAN = "edgenext_xxsmall"
MODEL_INPUT_IMAGE = "cam1/image_array"
INFERENCE_ENGINE = "tensorrt"  # TensorRT推奨
EPOCHS = 30
```

**どんな時に使う？**
- Jetsonで最高性能を引き出したい時
- 最新のエッジAI技術を体験したい時
- メモリが限られている時

### 5.3 モデル選択のガイド

#### 初心者向け

```
donkeycar → 最もバランスが良く、学習も速い
```

#### センサーのみで試したい

```

```

#### 高精度を目指す

```

```

#### 最新技術に挑戦

```
mobilevit_xxs → Transformer体験

```

## 6. 走行データを学習する

### 6.1 学習モデルの選択

`config.py`で使用するモデルを選択：

```python
# モデルタイプの選択
PLAN = "donkeycar"  # 軽量CNN（おすすめ）
# PLAN = "resnet18"  # 高精度（学習時間長い）
# PLAN = "nn"  # 超音波センサーのみ

# PLAN = "edgenext_xxsmall"  # エッジ最適化（TensorRT推奨）

# 学習パラメータ
EPOCHS = 30  # 学習回数（時間がない場合は10-15）
BATCH_SIZE = 64
```

### 6.2 学習の実行

```bash
python train_pytorch.py
```

#### 学習の流れ

1. **データセット自動選択**: 最新の記録データが選ばれる
2. **継続学習の確認**: 既存モデルがある場合は継続学習を選択可能
3. **学習開始**: エポックごとに損失値が表示される
4. **モデル保存**: 学習完了後、自動で保存される

#### 学習中の表示例

```
Epoch 1/30
Train Loss: 0.0234, Val Loss: 0.0198
Epoch 2/30
Train Loss: 0.0187, Val Loss: 0.0165
...
Best model saved: models/donkeycar_20251205_150000.pth
```

### 6.3 学習の評価

- **損失値（Loss）**: 小さいほど良い
  - Train Loss: 訓練データでの誤差
  - Val Loss: 検証データでの誤差
- **過学習の確認**: Val Loss が Train Loss より大きく上回る場合は注意

#### 良い学習の例

```
Epoch 1: Train Loss: 0.050, Val Loss: 0.048
Epoch 10: Train Loss: 0.015, Val Loss: 0.016
Epoch 20: Train Loss: 0.008, Val Loss: 0.009
```

#### 過学習の例（避けるべき）

```
Epoch 1: Train Loss: 0.050, Val Loss: 0.048
Epoch 10: Train Loss: 0.010, Val Loss: 0.025
Epoch 20: Train Loss: 0.003, Val Loss: 0.040  ← Val Lossが増加
```

学習完了後、推論を高速化できます：


#### Raspberry Piの場合（OpenVINO）


変換後、`config.py`で推論エンジンを変更：

## トラブルシューティング

### よくある問題と解決方法

#### センサーが動作しない

```bash
# デバイスが認識されているか確認
ls /dev/video*  # カメラ
i2cdetect -y 1  # I2Cデバイス

# LiDARの場合
ls /dev/ttyAMA0  # TMINI（シリアル接続）
ping 192.168.0.10  # UST-20（イーサネット接続、IPは環境に応じて変更）
```

#### LiDARが動作しない

```bash
# TMINIの場合：シリアルポート権限確認
sudo usermod -a -G dialout $USER
# 再ログインが必要

# UART設定確認（Raspberry Pi）
ls -l /dev/ttyAMA0

# UST-20の場合：ネットワーク接続確認
ping [LiDARのIPアドレス]

# LiDAR単体テスト
python lidar.py
```

#### ジョイスティックが反応しない

```bash
# ジョイスティックのテスト
jstest /dev/input/js0

# config.pyのデバイスファイルを確認
JOYSTICK_DEVICE_FILE = "/dev/input/js0"
```

#### モデルが読み込めない

```bash
# モデルファイルの存在を確認
ls -la models/

# config.pyのMODEL_NAMEを確認
```

#### 学習が進まない

- データ量を確認（1000フレーム以上推奨）
- データの質を確認（滑らかな操作ができているか）
- エポック数を増やす
